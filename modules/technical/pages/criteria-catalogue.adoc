=== Criterion (cac:TenderingCriterion)

[cols="1,4",options="header"]
|===
|*Class name*: |cac:TenderingCriterion
|*Definition*: |A tendering criterion describes a fact or a condition that is used by the contracting body to evaluate and compare tenders by economic operators and which will be used for the exclusion and the selection of candidate tenderers to the award decision.
|*Business rule(s)*: |BR-LOT-20, BR-LOT-30, BR-LOT-30-S20, Common (BR-TC-01)
|*File*: |ubl-2.4/xsdrt/common/UBL-CommonAggregateComponents-2.4.xsd
|*Path*: |/QualificationApplicationRequest/cac:TenderingCriterion
|===

[cols="3,1,1,5,5",options="header"]
|===
|*Components* |*Type* |*Card* |*Description* |*Requirements*

|*cbc:ID*
|Identifier
|1
|A language-independent token that allows to identify a criterion uniquely.
a|
*Rule*: Each Criterion is defined in e-Certis and must use the UUID supplied by e-Certis. See also link:{url-tree}/criterion/espd-edm.json[espd-edm.json].

*Rule scope*: Common (BR-TC-02, BR-TC-12, BR-TC-13, BR-OTH-02)

|*cbc:CriterionTypeCode*
|Code
|1
|A classification code defined by the ESPD-EDM to represent the criterion in the ESPD taxonomy.
a|
*Rule*: Compulsory use of codes from e-Certis (e.g. crime-org, corruption, chain-manage).

*Rule scope*: Common (BR-REQ-30, BR-TC-03, BR-TC-04, BR-OTH-01, BR-OTH-03)

|*cbc:Name*
|Text
|1
|A short and descriptive name for a criterion.
a|
*Rule*: The name should match the one from e-Certis.

*Rule scope*: Common (BR-TC-05)

|*cbc:Description*
|Text
|1..n
|An extended description of the criterion.
a|
*Rule*: The description should match the one from e-Certis.

*Rule scope*: Common (BR-TC-06, BR-TC-19)

|*cac:ProcurementProjectLotReference*
|Class
|0..n
|One or more procurement project lots to which this criterion relates.
a|
*Rule*: Mandatory for all Selection Criteria (1..n). Not necessary for exclusion grounds.

See xref:lots-management.adoc[Lots Management].

|*cac:SubTenderingCriterion*
|Class
|0..n
|Descendant criteria used to define national exclusion criteria that specialise EU criteria.
a|
*Rule*: A sub-criterion 'is a' criterion.

|*cac:Legislation*
|Class
|0..n
|A reference to the legislation related to the Criterion.
|See <<legislation>> below.

|*cac:TenderingCriterionPropertyGroup*
|Class
|1..n
|The first level group of properties and sub-groups of properties.
a|
*Rule scope*: Common (BR-TC-07, BR-TC-16)

|===

== Data Structure Vocabulary

The ESPD-EDM data structure vocabulary maps to UBL-2.4 elements as follows:

[cols="1,3",options="header"]
|===
|ESPD-EDM Vocabulary |UBL-2.4 Element

|CRITERION |`cac:TenderingCriterion`
|SUBCRITERION |`cac:SubTenderingCriterion`
|REQUIREMENT_GROUP |`cac:TenderingCriterionPropertyGroup`
|QUESTION_GROUP |`cac:TenderingCriterionPropertyGroup`
|REQUIREMENT_SUBGROUP |`cac:SubsidiaryTenderingCriterionPropertyGroup`
|QUESTION_SUBGROUP |`cac:SubsidiaryTenderingCriterionPropertyGroup`
|CAPTION |`cac:TenderingCriterionProperty` (TypeCode=CAPTION)
|REQUIREMENT |`cac:TenderingCriterionProperty` (TypeCode=REQUIREMENT)
|QUESTION |`cac:TenderingCriterionProperty` (TypeCode=QUESTION)
|ADDITIONAL_DESCRIPTION_LINE |`cbc:Description` (in `cac:TenderingCriterion`)
|LEGISLATION |`cac:Legislation`
|===

The vocabulary is defined in the code list link:{url-tree}/codelists/CriterionElementType.gc[CriterionElementType].

== Criterion Data Source

Starting with ESPD-EDM v5.0.0, criterion definitions are maintained in JSON format (`espd-edm.json`), replacing the deprecated Excel-based workflow. See xref:distribution-tooling.adoc[Distribution and Tooling] for details on the JSON data model.
