== Request and Response Concepts

The ESPD data exchange is based on two complementary XML documents that together form the qualification dialogue between buyer and offering party.

=== ESPD Request

The ESPD Request is created by the *buyer* and defines:

* The exclusion grounds applicable to the procedure (mandatory + discretionary)
* The selection criteria the economic operator must meet
* Requirements and thresholds for selection criteria
* References to the Contract Notice and procurement procedure
* Lot associations for selection criteria

The Request uses the UBL 2.4 document type `QualificationApplicationRequest`.

=== ESPD Response

The ESPD Response is created by the *economic operator* and provides:

* Self-declarations answering each exclusion ground and selection criterion
* Response values matching the data types specified in the Request
* References to evidence documents proving compliance
* Economic operator identification and role information
* Lot indication (which lot(s) the EO tenders for)

The Response uses the UBL 2.4 document type `QualificationApplicationResponse`.

=== Relationship between Request and Response

* The Response *must include all criteria* from the Request
* Each Response answer is linked to a specific criterion property via UUID (`cbc:ValidatedCriterionPropertyID`)
* The Response references the Request via `cac:AdditionalDocumentReference`
* One ESPD Response per economic operator per lot

=== Data flow

```
Buyer → ESPD Request → published with Contract Notice
                              ↓
Economic Operator → retrieves Request
                              ↓
Economic Operator → creates ESPD Response
                              ↓
                    submits with the tender (open procedure) or with the
                    request to participate (multi-stage procedures)
                              ↓
Buyer → evaluates Responses → selects candidates
```

NOTE: In open procedures the ESPD Response is submitted together with the tender. In multi-stage procedures (restricted, competitive procedure with negotiation, competitive dialogue, innovation partnership) it is submitted with the request to participate — before any tender exists.

=== Above-threshold and below-threshold use

The same ESPD documents are used regardless of the value of the procurement, but some obligations differ depending on whether the procedure is above or below the EU thresholds defined in Article 4 of Directive 2014/24/EU:

[cols="1,3",options="header"]
|===
|Context |What differs

|*Above the threshold*
|The ESPD Request *must* reference the Contract Notice published on TED (via `cac:AdditionalDocumentReference`). Exclusion grounds under Article 57(1) and (2) are mandatory.

|*Below the threshold*
|National rules apply (respecting the general principles of EU law). The buyer may identify the procedure directly in the ESPD Request without a TED publication reference.
|===

In both cases the XML structure is identical (`QualificationApplicationRequest` / `QualificationApplicationResponse`). The `cbc:ProfileExecutionID` element in the root of the document identifies the ESPD-EDM version in use (for v5.0.0, `ESPD-EDMv5.0.0`).

NOTE: Earlier versions of the ESPD-EDM distinguished separate document profiles — "Regulated" and "Self-Contained" (renamed "Basic" and "Extended" from v2.1.1). From v3.0.0 onward these profile variants were removed: there is a single profile per version, and the above/below-threshold difference is a matter of which information and business rules apply, not a separate document type.
