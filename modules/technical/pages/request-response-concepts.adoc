== Request and Response Concepts

The ESPD data exchange is based on two complementary XML documents that together form the qualification dialogue between buyer and offering party.

=== ESPD Request

The ESPD Request is created by the *buyer* (Contracting Authority) and defines:

* The exclusion grounds applicable to the procedure (mandatory + discretionary)
* The selection criteria the economic operator must meet
* Requirements and thresholds for selection criteria
* References to the Contract Notice and procurement procedure
* Lot associations for selection criteria

The Request uses the UBL 2.4 document type `QualificationApplicationRequest`.

=== ESPD Response

The ESPD Response is created by the *economic operator* and provides:

* Self-declarations answering each exclusion ground and selection criterion
* Response values matching the data types specified in the Request
* References to evidence documents proving compliance
* Economic operator identification and role information
* Lot indication (which lot(s) the EO tenders for)

The Response uses the UBL 2.4 document type `QualificationApplicationResponse`.

=== Relationship between Request and Response

* The Response *must include all criteria* from the Request
* Each Response answer is linked to a specific criterion property via UUID (`cbc:ValidatedCriterionPropertyID`)
* The Response references the Request via `cac:AdditionalDocumentReference`
* One ESPD Response per economic operator per lot

=== Data flow

```
Buyer → ESPD Request → published with Contract Notice
                              ↓
Economic Operator → retrieves Request
                              ↓
Economic Operator → creates ESPD Response
                              ↓
                    submits with tender
                              ↓
Buyer → evaluates Responses → selects candidates
```

=== Self-contained vs regulated ESPD

The ESPD-EDM supports two usage patterns depending on the procurement context:

[cols="1,3",options="header"]
|===
|Variant |Description

|*Regulated (above threshold)*
|For procurement procedures above the EU thresholds defined in Article 4 of Directive 2014/24/EU. The ESPD Request *must* reference a Contract Notice published on TED. Exclusion grounds from Article 57(1) and (2) are mandatory. The full set of ESPD-EDM business rules applies, including lot management via eForms-aligned identifiers.

|*Self-contained (below threshold)*
|For procedures below the threshold or where Member State legislation permits simplified use. The buyer may include all necessary procedure information directly in the ESPD Request without a TED publication reference. The ESPD document is "self-contained" — it carries the procedure context within itself.
|===

In both variants the XML structure is the same (`QualificationApplicationRequest` / `QualificationApplicationResponse`). The difference lies in:

* Whether `cac:AdditionalDocumentReference` references an external TED publication or not
* Which exclusion grounds are mandatory vs optional
* Whether lot identifiers follow the eForms format

The `cbc:ProfileExecutionID` element in the root of the document identifies which profile is in use.
