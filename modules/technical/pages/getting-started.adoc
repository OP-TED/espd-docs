== Getting Started with ESPD-EDM Implementation

The ESPD Exchange Data Model (ESPD-EDM) assists developers in building ESPD Services. It provides a model that ensures the ESPD Request and ESPD Response XML files produced across all services are consistent and comply with EU procurement legislation.

=== Prerequisites

To implement an ESPD Service based on ESPD-EDM v5.0.0, you need:

* A development environment with *Java JDK 1.8+* (for XSD/Schematron validation via Saxon)
* An *XML editor or IDE* capable of working with XSD schemas and XSLT (e.g. VS Code, IntelliJ, Oxygen XML)
* *Git client* to clone the ESPD-EDM repository
* Familiarity with *UBL 2.4 XML* document structures
* Optionally: *Node.js 18+* (only if you plan to work with the criterion generation tooling)

=== Quick Start

[arabic]
. *Clone the repository*:
+
[source,bash]
----
git clone https://github.com/OP-TED/ESPD-EDM.git
cd ESPD-EDM
git checkout v5.0.0
----

. *Explore the structure*: review `criterion/espd-edm.json` (criterion definitions), `codelists/` (code lists), and `schemas/` (UBL XSD schemas).

. *Validate an example*: submit one of the sample XML files from `validation/` to the https://www.itb.ec.europa.eu/espd/upload[Interoperability Testbed] to see the validation in action.

. *Understand the schemas*: open `schemas/maindoc/UBL-QualificationApplicationRequest-2.4.xsd` and `UBL-QualificationApplicationResponse-2.4.xsd` to see the document structures your service must produce.

. *Read the criterion JSON*: parse `criterion/espd-edm.json` to understand the criterion tree your service needs to render as a form and serialise as XML.

The architecture components interact to produce the ESPD UBL XML Request and Response documents:

* *UBL (Universal Business Language)* — defines the XML elements and attributes used in ESPD documents. ESPD-EDM v5.0.0 uses UBL 2.4.
* *UML Model* — describes the Request and Response model elements, their attributes, relationships, and cardinalities. Maintained in Enterprise Architect.
* *Criterion Data Structure (JSON)* — defines each criterion and its hierarchical tree of properties. Created as a JSON file (`espd-edm.json`) extracted from Enterprise Architect.
* *ESPD UBL XML* — the resulting ESPD Request and Response XML files. An ESPD service produces these by rendering the criterion data structure as a form and serialising the answers as UBL 2.4 XML.
* *Code Lists (Genericode)* — attribute-value structure of codes for each code list, distributed as `.gc` files. Metadata is defined in `codelists.json`.
* *Validation (Schematron)* — validates generated ESPD XML files against UBL schema and ESPD-specific business rules.

== Key Standards

[cols="1,3",options="header"]
|===
|Standard |Role in ESPD-EDM

|link:https://docs.oasis-open.org/ubl/os-UBL-2.4/UBL-2.4.html[UBL 2.4]
|Base XML schema. ESPD uses `QualificationApplicationRequest` and `QualificationApplicationResponse` document types.

|link:https://www.schematron.com/[ISO Schematron]
|Rule-based validation of ESPD XML instances beyond what XSD can enforce.

|link:https://docs.oasis-open.org/codelist/genericode/doc/oasis-code-list-representation-genericode.html[Genericode 1.0]
|Format for distributing code lists used in ESPD documents.

|link:https://www.w3.org/TR/xslt-30/[XSLT 3.0]
|Transformation language used in the validation pipeline to compile Schematron rules into executable XSL.

|===

== Distribution Package

The ESPD-EDM distribution package is available at https://github.com/OP-TED/ESPD-EDM/tree/v5.0.0[GitHub]. It contains:

[cols="1,3",options="header"]
|===
|Folder |Contents

|`codelists/`
|Genericode (`.gc`) files for all code lists + `codelists.json` metadata reference.

|`criterion/`
|Criterion definitions in JSON format (`espd-edm.json`) + JSON schema for validation.

|`schemas/`
|Official UBL 2.4 distribution files (XSD schemas) from OASIS.

|`validation/`
|Schematron source files (`.sch`) and compiled XSL files for ESPD Request and Response validation.

|`xml-examples/`
|Sample ESPD Request and Response XML documents.

|===

For more details on the distribution package, see xref:distribution-tooling.adoc[Distribution and Tooling].
