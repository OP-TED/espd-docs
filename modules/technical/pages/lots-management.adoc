== Lots Management in ESPD

The ESPD includes a specific approach to lot management, aligned with eForms. This page describes the unified lot handling logic across both ESPD Request and ESPD Response documents.

== Overview

In ESPD-EDM v5.0.0, the lot management follows this logic:

* There is *one ESPD Request* per procurement procedure, containing the exclusion grounds and selection criteria.
* Exclusion grounds are *general* — they apply to all lots in the procedure.
* Selection criteria are *lot-specific* — different lots may have different selection criteria. Each selection criterion includes a reference to the lot(s) it applies to via `cac:ProcurementProjectLotReference`.
* On the Economic Operator's side, there are *as many ESPD Responses as lots* (or groups of lots) the EO tenders for.

== Lots in the ESPD Request

The ESPD Request includes selection criteria with a reference to the lots they apply to, using the UBL-2.4 element `cac:ProcurementProjectLotReference`:

[source,xml]
----
<cac:TenderingCriterion>
  <cbc:ID>...</cbc:ID>
  <cbc:CriterionTypeCode>...</cbc:CriterionTypeCode>
  <!-- ... -->
  <cac:ProcurementProjectLotReference>
    <cbc:ID>LOT-0001</cbc:ID>
  </cac:ProcurementProjectLotReference>
  <cac:ProcurementProjectLotReference>
    <cbc:ID>LOT-0002</cbc:ID>
  </cac:ProcurementProjectLotReference>
</cac:TenderingCriterion>
----

*Rules:*

* This element is mandatory for all selection criteria with cardinality `1..n` because different selection criteria can be associated with different procurement lots.
* This element is not necessary for exclusion grounds because exclusion grounds apply to all lots automatically.
* Rule scope: BR-LOT-40 (Lots apply only to Selection Criteria; Exclusion Criteria cannot have Lot associated), BR-LOT-41 (All Selection Criteria must have associated LOT).

== Lot Identifiers

To keep the ESPD aligned with the notice it belongs to, this version of the ESPD adopts the eForms lot identifier format instead of defining its own. The same identifiers used in the eForms Contract Notice are reused, unchanged, in the ESPD Request and ESPD Response. This guarantees that a selection criterion associated with `LOT-0002` in the ESPD refers to exactly the same lot as `LOT-0002` in the notice.

Identifiers follow a fixed prefix + zero-padded sequence number pattern:

[cols="1,2,2",options="header"]
|===
|Identifier |Pattern |Meaning

|Single lot
|`LOT-nnnn`
|An individual lot in the procedure (e.g. `LOT-0001`, `LOT-0002`).

|Group of lots
|`GLO-nnnn`
|A group of lots that are tendered for and awarded together (e.g. `GLO-0001`).

|Whole procedure
|`LOT-0000`
|Used when the procedure is not divided into lots — a single, procedure-wide lot.
|===

The four-digit sequence is zero-padded (`0001`, not `1`) and numbering starts at `0001` for lots and groups. A procedure that is not split into lots still carries one lot, conventionally `LOT-0000`.

These identifiers are the values carried by `cac:ProcurementProjectLotReference/cbc:ID` in both ESPD documents. Because the format is defined by eForms rather than the ESPD-EDM, the authoritative rules for allowed values live in the eForms specification; the ESPD simply consumes them.

== Lots in the ESPD Response

On the Economic Operator's side:

* If the EO wants to participate in 3 lots, the EO must fill in *3 separate ESPD Responses*.
* Each ESPD Response indicates which lot it refers to via `cac:ProcurementProjectLotReference`.
* The EO must respond to *all exclusion grounds* in every response (they apply to all lots).
* The EO must respond to the *selection criteria applicable to the specific lot*.

*Rule scope:* BR-LOT-10 (The lot the EO tenders for MUST be provided).

== Summary

[cols="1,2,2",options="header"]
|===
|Aspect |ESPD Request |ESPD Response

|Number of documents
|1 per procedure
|1 per lot (or group of lots) per EO

|Exclusion grounds
|Apply to all lots (no lot reference needed)
|Must be answered in every response

|Selection criteria
|Must reference applicable lot(s) via `cac:ProcurementProjectLotReference`
|Only criteria for the targeted lot must be answered

|Lot identifier format
|eForms format: `LOT-0001`, `GLO-0001`
|Same identifiers as in the Request

|===
