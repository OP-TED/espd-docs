== Business Requirements Specification

The ESPD-EDM models the business and information requirements for the ESPD Response transaction in accordance with Directive 2014/24/EU (Article 59) and Commission Implementing Regulation (EU) 2016/7. The formal information requirements are defined in the xref:response-reference-model.adoc[Response Reference Model].

[cols="1,2"]
|===
|*BUSINESS REQUIREMENT* |*The ESPD Response document must include all the criteria that are present in the ESPD Request. For certain selection criteria the economic operator can add additional properties so it can include more responses than the minimum required by the buyer.*
|===

== Economic Operator

The economic operator information is spread in two places:

[arabic]
. The UBL-2.4 *cac:EconomicOperatorParty* component (identification, role, party data);
. *Criteria data structures* — the "Other" (`code` `OT`) criteria (`type` `CRITERION`) that carry economic-operator information, such as SME status (`OT65`) and sheltered workshop (`OT57`), together with the questions on group participation, reliance on the capacities of other entities, and subcontracting.

NOTE: The economic operator's party data is modelled by the `info-eo` *INFORMATION* structure (`ECONOMIC_OPERATOR_PARTY`), which maps to the UBL `cac:EconomicOperatorParty` component described above.

=== Key requirements

* *One ESPD Response per economic operator* — every participant in a tender must provide its own ESPD Response.
* *One ESPD Response per lot* — each EO submits a separate response per lot (or group of lots) they tender for.
* *Group name consistency* — all economic operators in a group must use the exact same group name spelling.

=== Roles

The role of the economic operator is specified via `cac:EconomicOperatorRole/cbc:RoleCode` using code list link:{url-tree}/codelists/EoRoleType.gc[EoRoleType]:

* Sole tenderer
* Group leader
* Group member (not leader)
* Other entity (relied upon)
* Subcontractor

For detailed element tables, see xref:response-reference-model.adoc[Response Reference Model].

== Answering QUESTIONs

The ESPD Response uses `cac:TenderingCriterionResponse` to answer each QUESTION from the Request. Key rules:

* Each response is linked to one, and only one, criterion property via `cbc:ValidatedCriterionPropertyID`, which carries the ID of that property from the Request. (In `espd-edm.json` the same linkage is expressed through the `responsepath` / `contentpath` values; top-level criterion UUIDs — harmonised with eCertis — identify the criterion, not the individual property.)
* One response may contain a list of `cac:ResponseValue` elements of the same type.
* If confidential, linked evidences must also be treated as confidential.
* Response data types must match the `cbc:ValueDataTypeCode` specified by the buyer in the Request.

For the criterion-property-response linking mechanism, see xref:how-criteria-work.adoc[How Criteria Work].

== Evidence

Economic operators can reference evidence documents that prove compliance with criteria. Evidence is linked indirectly to responses: `cac:EvidenceSupplied/cbc:ID` in the response references `cac:Evidence/cbc:ID` at document level.

Key elements:
* `cac:Evidence/cbc:ID` — unique identifier for the evidence
* `cac:Evidence/cbc:ConfidentialityLevelCode` — access right (PUBLIC, CONFIDENTIAL)
* `cac:Evidence/cac:DocumentReference` — contains the URI, verification code, and issuer

For detailed element tables, see xref:response-reference-model.adoc[Response Reference Model].

== Lot Management in the Response

In the ESPD Response, `cac:ProcurementProjectLot` under the root element defines which lot(s) the EO is answering for. See xref:lots-management.adoc[Lots Management] for full details.
