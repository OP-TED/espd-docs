== Migration from v4 to v5

This page provides guidance for migrating ESPD Service implementations from ESPD-EDM v4.x to v5.0.0.

=== Summary of breaking changes

[cols="1,3",options="header"]
|===
|Area |Change

|UBL version
|Upgraded from UBL 2.3 to *UBL 2.4*. Schema folder renamed from `ubl-2.3/` to `schemas/`.

|Criterion code lists
|The single `Criterion` code list is *replaced* by two separate lists: `ExclusionGround` and `SelectionCriterion` (from EU Vocabularies).

|Criterion data format
|Excel-based `ESPD-criterion.xlsx` is *deprecated*. The canonical source is now `espd-edm.json` (JSON format).

|Code list versions
|All ESPD-managed code lists updated from version `4.0.0` to `5.0.0`. EU Vocabularies code lists updated to latest published versions.

|Schematron validation
|`listVersionID` validation now checks for prefix `5.` (was `3.` or `4.`). Rule `BR-OTH-01-40` enforces this.

|UBLVersionID value
|Must be `"2.4"` (was `"2.3"`). Rule `BR-OTH-05-01` enforces this.

|Repository structure
|`conceptual-model/` and `ubl-2.3/` folders removed. UBL 2.4 schema in `schemas/`. Added `codelists.json` metadata file.

|e-Certis harmonisation
|Criterion UUIDs harmonised with e-Certis. Some UUIDs changed. Deprecated criteria: C27 (authorisation) and C28 (membership) replaced by C66 (`slc-suit-auth-mbrshp`).

|New criteria
|Added EG C67 (`exg-mis-unrel-sec`) and SC C66 (`slc-suit-auth-mbrshp`).

|===

=== Migration steps

[arabic]
. Update XSD schema references from UBL 2.3 to UBL 2.4
. Replace `Criterion` code list usage with `ExclusionGround` + `SelectionCriterion`
. Update `cbc:UBLVersionID` value to `"2.4"`
. Update `listVersionID` attributes to `"5.0.0"` for ESPD-managed code lists
. Migrate criterion data consumption from Excel to JSON (`espd-edm.json`)
. Re-run Schematron validation against v5.0.0 rules
. Verify criterion UUIDs against updated e-Certis

=== Backwards compatibility

* UBL 2.4 is backwards compatible with UBL 2.3 at the schema level
* The ESPD Response still copies all criteria from the Request
* The property group structure (ONTRUE/ONFALSE logic) is unchanged
* BR rule IDs are preserved (same IDs, some extended)

=== New features requiring implementation updates

[cols="1,3",options="header"]
|===
|Feature |Impact on Implementers

|*JSON criterion data model*
|Services must consume `espd-edm.json` instead of the Excel file. The JSON provides a hierarchical part/section/criteria/components tree. See xref:technical:criterion-data-model-json.adoc[Criterion Data Model (JSON)].

|*eForms lot identifiers*
|Lot identifiers now follow the eForms pattern: `LOT-0001`, `LOT-0002`, `GLO-0001`. Services generating lot references must use this format.

|*Code list metadata (codelists.json)*
|A new `codelists.json` file provides machine-readable metadata for all code lists (identifiers, versions, agencies). Services managing code lists dynamically should consume this file.

|*Criterion UUID changes*
|Some criterion UUIDs changed due to e-Certis harmonisation. Services that hard-code UUIDs must update them. Deprecated criteria C27/C28 are replaced by C66.

|===

=== Deprecated features

The following features are deprecated in v5.0.0 and should no longer be used:

[cols="1,3",options="header"]
|===
|Feature |Replacement

|`ESPD-criterion.xlsx` (Excel criterion file)
|`criterion/espd-edm.json` (JSON format)

|`ubl-2.3/` folder
|`schemas/` folder (UBL 2.4)

|`conceptual-model/` folder in ESPD-EDM
|Separate https://github.com/OP-TED/espd-conceptual-model[espd-conceptual-model] repository

|ESPD Demo Site (`docs.ted.europa.eu/espd-demo/`)
|https://github.com/OP-TED/espd-service-sandbox[ESPD Service Reference Implementation] (in development)

|Single `Criterion` code list
|Split into `ExclusionGround` + `SelectionCriterion` (EU Vocabularies)

|===

=== Migration checklist

Use this checklist to verify your migration is complete:

* [ ] XSD schemas updated to UBL 2.4 (`schemas/maindoc/`)
* [ ] `cbc:UBLVersionID` set to `"2.4"` in generated documents
* [ ] `cbc:CustomizationID` updated to reference ESPD-EDM v5.0.0
* [ ] All `listVersionID` attributes updated to `"5.0.0"` for ESPD-managed code lists
* [ ] Criterion data sourced from `espd-edm.json` (not Excel)
* [ ] Code list references split: `ExclusionGround` + `SelectionCriterion` (not single `Criterion` list)
* [ ] Lot identifiers use eForms format (`LOT-0001`)
* [ ] Criterion UUIDs verified against e-Certis (check C27, C28 -> C66 migration)
* [ ] Schematron validation passes against v5.0.0 XSL rules
* [ ] ESPD Request and Response validated on https://www.itb.ec.europa.eu/espd/upload[Interoperability Testbed]

=== Verifying the migration

After completing the migration steps:

[arabic]
. Generate a sample ESPD Request and Response with your updated service
. Validate both documents against the v5.0.0 Schematron XSL files (locally or via the Testbed)
. Verify that no `BR-OTH-01-40` errors appear (code list version mismatch)
. Verify that no `BR-OTH-05-01` errors appear (UBL version mismatch)
. Cross-check criterion UUIDs in your documents against `espd-edm.json`
